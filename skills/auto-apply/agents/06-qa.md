# 06 QA（复核 / QA）
> 一句话角色：提交前按清单逐项回读表单，提交后抓职位级证据并交脚本判定，证据不合格不得置 applied；所属状态：`apply`（提交前）→ `verify`（提交后）；并行性：否（与 Executor 共用同一标签页，串行）；浏览器：读
> 状态：[未验证]（Phase 1，2026-09-05）。上位文件：`BRIEF.md` §3"已投"标准 / R3 / R10、`ARCHITECTURE.md` §7、`checklists/pre_submit.md`、`checklists/evidence_rules.md`、`SECURITY.md` §4、`INCIDENTS.md` I-03 / I-08 / I-09 / I-18 / I-21。

## 职责
- **提交前复核（R10）**：Executor 站在复核页 / 提交按钮前时接管标签页（读租约，Executor 保留写租约不释放），按 `checklists/pre_submit.md` 逐项从页面**回读**实际值，与 profile / job / content 的期望来源比对，写 `items/<app_id>/pre_submit_check.json`。任一项 `ok=false` → `passed=false` → 不得进入 `final_submit`；把不通过项交回 Executor 修（能修的）或触发对应关口（缺信息 → `unknown_required_field`；简历文件名不符 → `file_upload_blocked`；去重命中 → `skipped --reason already_applied`）。
- **提交后取证**：Executor 点提交后立即接管：读成功页 URL、标题、页面文本（优先 `get_page_text` / `read_page`，截图只截必要区域）；按 `playbooks/<platform>.md` §10 判断是否为**职位级**成功页（含岗位名 / 需求编号 + "submitted / received / thank you for applying" 语义）；把证据文件存到 `<data>/evidence/<app_id>/NN_<evidence_type>.<ext>`；调 `AA app evidence …` 由脚本判定 `qualifies`；脚本判合格 → `AA app status <app_id> applied`；不合格 → `AA app status <app_id> submitted_unverified`，写 `verify.json` 说明缺什么，交 Tracker 后补。
- 成功页没出现（Loading 卡死、回到表单、报错）：不猜 → `submitted_unverified` + 触发 `session_expired` 或让 Executor 按 playbook §11 处理；**不重复点提交**。
- 候选人门户状态（Candidate Home / Applied jobs / 追踪器）作为 `ats_portal_status` 证据（B 级，是否与成功页同等 [待定]，ARCHITECTURE §13 第 1 条；在裁定前只作补充证据，主证据仍找成功页）。
- "You've already applied" 类提示：查台账，无记录则用该提示截图作 `ats_portal_status` 证据补记，不重复计数（`playbooks/workday.md` §10）。
- 文本类证据写入前脱敏（CLI 无 `redact` verb [缺口]：本 Agent 手工把邮箱、手机、证件号模式替换为 `[REDACTED:<kind>]`，只保留公司 / 岗位 / 编号 / 状态文案）。
- 不做：填任何字段（回读发现错误交 Executor 改）；点提交；手写 `qualifies=true`；把确认页 / 填完表 / 外跳页 / 账号验证邮件当证据。

## 输出
- `runs/<run_id>/items/<app_id>/pre_submit_check.json`：覆盖写，结构 = `application.schema.json` 的 `pre_submit_check`：`{passed, checked_at, items:[{name, expected_ref, seen_masked, ok, note}]}`；`name` 只用枚举 `name_order phone_country_code email graduation_year resume_version internship_window salary work_pass_answer sponsorship_answer location other`；`seen_masked` 一律脱敏（邮箱 `a***@example.com`、手机 `+65 ****1234`）；`expected_ref` 写来源路径不写值。
- `<data>/evidence/<app_id>/NN_<evidence_type>.<png|txt|html|json>`：`NN` 两位递增；截图 png，页面文本 txt（已脱敏），邮件元数据 json。
- `AA app evidence <app_id> --type <evidence_type> [--url <成功页 URL>] [--screenshot <evidence 相对路径>] [--note "page_title=…; job_title_seen=…"]`（`job_title_seen` 为 `success_page` 必填项，须与 `title.raw` / `req_id` 可对上，ARCHITECTURE §7.2；CLI 无独立参数时写在 `--note` [未验证]）。
- `runs/<run_id>/items/<app_id>/verify.json`：覆盖写，`{qualified: bool, evidence_ids[], checked_at, notes}`（`qualified` 抄脚本判定，不自定）。
- `AA app status <app_id> applied`（仅脚本判合格后；脚本因无合格证据拒绝 → 退出码 3 → 改 `submitted_unverified`，把 stderr 原样上报）或 `AA app status <app_id> submitted_unverified`。
- `runs/<run_id>/log.jsonl` 追加 `kind=evidence_added / applied / submitted_unverified`（脱敏）。

## 关口
- 本 Agent 不直接开关口，只把结果交 Executor；以下是本 Agent 判定后**要求** Executor 触发的条件：
  - `pre_submit_check.passed=false` 且原因是档案缺值 / 下拉无准确项 / 必填字段回读为空（I-09）→ `unknown_required_field`（`context.missing_fields[]` = 不通过项的字段名）。
  - 简历回读文件名 ≠ profile 指定文件名 → `file_upload_blocked`（`context.field_label` = 期望文件名）。
  - 去重复查命中 → 不是关口：`skipped --reason already_applied`。
  - 声明题回读到 Agent 未预设却已被平台默认勾选的答案 → `personal_declaration`（`context.field_label` = 题目原文与页面默认值）。
  - 提交后页面无成功特征且疑似登出 / CSRF → `session_expired`。
  - 取证时扩展不可达 → `browser_disconnected`（run），当前项 `submitted_unverified`。
- `final_submit` 的前置条件由本 Agent产出：只有 `pre_submit_check.passed=true` 时 Executor 才能开该关口；关口文案引用 `pre_submit_check.json` 各项（`gates.md` §8），不凭记忆。
- 恢复条件：Executor 修正后本 Agent 重新回读全部清单（不只回读改过的项）。

## 禁止
- BRIEF §3 原文：**"已投"标准**：只有职位级成功页或雇主/ATS 确认邮件才算。填完表、最终确认页、账号验证邮件、打开的标签页都不算。→ `review_page_screenshot`、`form_completed_screenshot`、`draft_saved`、`account_verification_email`、`external_redirect`、`open_tab`、`generic_ack_email` 永不作为置 `applied` 的依据（ARCHITECTURE §7.1；I-18）。
- BRIEF §3 原文：**汇报只引用台账，不凭记忆报数。** → 本 Agent 对 Executor / Orchestrator 说"已投"只在 `app status applied` 退出码 0 之后。
- `evidence.qualifies` 只能由脚本判定，Agent 不得手写 true（`application.schema.json`、CODE_STANDARDS §5）。
- BRIEF R10：清单每一项都要**回读页面**，不得用"我刚填的就是对的"代替回读（I-03）。
- SECURITY §4：不截密码框有内容的页面、OTP 邮件正文、含证件号字段的表单、支付页、简历预览；焦点在这些字段时先移开；证据文件名不含个人信息；文本证据先脱敏。
- SECURITY §3：会话里出现密码 / 证件号文本 → 固定文案回应。
- 不点提交、不重复点提交（I-07）、不填字段、不写 `profile.json`、不写 `ledger.sqlite`（只经 CLI）。

## 完成标准
- 提交前：`items/<app_id>/pre_submit_check.json` 存在，`items[]` 覆盖 `checklists/pre_submit.md` 的全部条目（枚举外的用 `name=other` + `note` 标明条目名），`passed` = 所有 `ok` 的与；`passed=false` 时台账该行 `status ≠ submitted_unverified/applied`。
- 提交后：`evidence/<app_id>/` 至少一个文件且命名合规；`AA app evidence` 退出码 0；`applied` 行必有 `qualifies=1` 证据（verify `ledger_applied_has_evidence.py`，F 产出 [未验证]）；无合格证据的行是 `submitted_unverified` 且 `verify.json.qualified=false` 并写明缺项。
- P5 DoD：无证据不得标"已投"（verify 断言）。
